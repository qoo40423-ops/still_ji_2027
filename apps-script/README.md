# 紀家烘焙坊｜116 年中秋 TEST 後端（第一階段）

## 目前完成
- 已依照 **現有** Google 試算表的實際欄位順序對接，不會建立「自取訂單／宅配訂單」等多餘分頁。
- 對應三張表：**門市自取**（18 欄）、**宅配到府**（25 欄）、**每日產能統計**（A:H）。
- 一筆訂單一列，付款狀態直接放在訂單列。
- 伺服器重新計算價格、運費、偏遠費、商品顆數與每日產能，不採信前端提供的總金額。
- 訂單建立時間、72 小時付款截止時間、唯一訂單編號、初始付款狀態「未付款」。
- Script Lock、requestId 去重，防止重複送單與同時搶占產能。
- 自取／宅配共用每日 4,800 顆上限；已取消、作廢及退款完成訂單不計入。
- 自取支援手機及市話，平日／週末／9 月 15 日的時段限制。
- 宅配支援 6 入 4／10／15 盒組、15 入盒數、提袋分配、宜花東每箱 +10。
- 產能統計只更新 A:H，保留試算表 I 欄以後原有說明。

## 第一次使用：**請勿直接執行新增訂單**
1. 在這份 TEST Google 試算表中選「擴充功能 → Apps Script」，建立**綁定這份試算表**的測試 Apps Script 專案。
2. 將本資料夾 `Code.gs` **完整內容**貼入 Apps Script 編輯器，儲存。
3. 先選擇並執行 `testInspect2027`，授權後確認執行紀錄的三張工作表都顯示 `headersOk: true`。
4. 唯讀檢查通過後，再手動執行 `testCreatePickup2027`，確認「門市自取」新增一筆測試資料、付款狀態及截止時間正確。
5. 再執行 `testCreateDelivery2027`，確認「宅配到府」新增一筆資料，並檢查「每日產能統計」。
6. 測試完成後，請將測試資料的「訂單狀態」設為「已取消」，並執行 `refreshCapacitySummary2027`；若要刪除測試列，請先備份。

## 注意
- **目前沒有 doPost／doGet，GitHub Pages 仍無法正式送單。**
- 此階段尚未啟用自動取消、LINE 推播、核帳確認、查單身分驗證、宅配單客戶確認或正式退款作業。
- **備註輸入 8888 不構成授權**。前端優惠試算僅供展示；後端目前拒絕 `staffApproved: true`，不會擅自給員工價。正式版須採安全的管理端核准機制。
- 宅配最晚出貨日、退款日期仍待公告，因此後端目前只限制展示日期範圍及週末，不以舊的截止日阻擋。
- 試算表的原有公式與樣式盡量保留，但寫入新訂單時會覆寫該筆資料列 A:R 或 A:Y 的預填公式，改以伺服器算好的數值為準。
- **目前僅限測試環境，請勿部署為任何人都可使用的公開 Web App。**
- 管理員手動更改日期、數量、狀態後，請執行 `refreshCapacitySummary2027` 更新統計；目前不會自動檢查手動修改是否超量。
- 請勿將客人個資、金鑰或私人 Apps Script 部署網址提交到公開 GitHub。
