# 2027 中秋 Apps Script 測試後端

## 用途
- 一份 Google 試算表，三個工作表：「自取訂單」、「宅配訂單」、「每日產能統計」。兩張訂單表各自一筆訂單一列。
- 自取與宅配依「製作日期」合併占用每日 4,800 顆（80 盤）額度。
- 每筆訂單顆數 = 6 入盒數 × 6 + 15 入盒數 × 15。
- 使用 Script Lock 將「查詢餘額 → 寫入訂單」包在同一鎖內，降低同時送單超賣風險。
- 同一 requestId 重送不重複占用產能。
- 「已取消／取消／作廢／退款完成」不再計入產能；其他狀態（包含待確認、未付款）計入，避免超賣。
- 宅配週六、週日禁止選擇；6 入 4 盒組最晚 **出貨** 2027/08/31；6 入 15 盒組最晚 **出貨** 2027/09/10。
- 15 入宅配最低 4 盒，每箱最多 10 盒、每箱運費 $210，宜花東每箱加 $10。
- 6 入固定組合：4／10／15 盒組；15 盒組提袋自動平均分配。
- 自取滿 4 盒贈袋尚未定案，**沒有自動套用**。

## 產能共用規則
- 自取以取貨／製作日期計入；宅配以出貨／製作日期計入，同一天合計不得超過 4,800 顆。
- 每次新增訂單都鎖定、同時讀取「自取訂單」及「宅配訂單」，確認合計剩餘產能後才寫入對應分頁。
- 「每日產能統計」列出自取顆數、宅配顆數、合計、總盤數、剩餘顆數及額滿狀態；新增訂單後自動更新。
- 重複請求識別碼跨兩張訂單表檢查，避免重複送單。

## 設定
1. 建立全新測試用 Google 試算表，請勿連到目前正式訂單表。
2. 在 Apps Script 專案新增 `Code.gs`，貼上本檔。
3. 專案設定 → 指令碼屬性新增 `SPREADSHEET_ID`，值為測試試算表 ID。
4. 手動執行一次 `setup2027()`，建立「自取訂單」、「宅配訂單」、「每日產能統計」。**不會搬移舊版「訂單總表」資料**，請使用全新測試試算表。
5. 測試 `createOrder2027(data)`、`capacityForDate2027('2027-09-10')`、`refreshCapacitySummary2027()`。
6. **目前尚未提供公開 doPost / doGet**，因此無法從 GitHub Pages 正式送單，也不會公開姓名電話資料。待確認訂單欄位、驗證、反濫用與查詢權限後再接上。

## 測試範例（在 Apps Script 編輯器手動執行）
```javascript
function testCreateOrder2027(){
  const result=createOrder2027({
    method:'宅配',
    name:'測試客人',
    phone:'0900000000',
    productionDate:'2027-09-10',
    four:0,ten:0,fifteenGroup:2,
    sixBoxes:30,fifteenBoxes:0,
    bags:6,remote:false,
    requestId:'TEST-2027-EXAMPLE-0001'
  });
  Logger.log(result);
}
```

測試後會寫入 **30×6 = 180 顆**、總額 **$9,460** 的一列。相同 requestId 重試應回傳原訂單。

- 自取可選日期、每日自取是否另設時段額度、9/15 上午 10 點提醒與退款作業。

- 管理者更改日期、數量或訂單狀態後，需執行 `refreshCapacitySummary2027()` 更新統計；**直接改表格不會自動阻擋超量**，且下一筆新訂單仍會重新讀取兩張表計算。
- 如同一日有多筆訂單，盤數應以總顆數 ÷ 60 向上取整；不要逐筆進位再加總作為容量判斷。
